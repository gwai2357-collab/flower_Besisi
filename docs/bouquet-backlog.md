# 꽃다발 백로그 (나중에 다룰 아이디어)

## 서비스 기본 흐름 (2026-11-07 정리)
- **주는 사람**은 두 가지 중에 고른다(편지 또는 음성 메모 포함). 여러 사람이 **한 다발을 함께 꾸미는** 기능은 없다(두 번째 버전 후보). 각자 만든 꽃을 한 사람에게 모아 보내는 "같이 보내기"는 첫 버전에 넣음(아래 "보내기 흐름").
  - **꽃 한 송이 (미니 다발)**: 생일처럼 가볍게 여러 사람에게 챙기는 선물. 꽃 한 송이를 소재 몇 줄기와 작은 포장으로 감싼 **아주 작은 다발** 모양으로 보낸다(아래 "미니 다발" 참고).
  - **직접 꾸민 꽃다발**: 부모·자식, 연인처럼 가까운 사이에 보내는 선물. 오늘 만든 선물 페이지들이 이 형태다.
- **받는 사람**은 받은 꽃들이 모이면, 그중 원하는 꽃을 골라 **직접 꽃다발로 묶고 꾸며서 보관**한다.
- **릴레이**: 내가 만든 꽃다발을 다른 사람에게 다시 전달할 수 있다.
- 흐름: 꽃 또는 꽃다발 받기 → 받은 꽃 모음 → 골라서 꽃다발 만들기 → 보관함·도감 → (선택) 릴레이로 전달
- 정한 것
  - 받은 꽃 한 송이는 **한 다발에만** 들어간다. 다발에 넣으면 모음에서 빠지고, 다발을 풀면 돌아온다.
  - 릴레이는 **모양을 복사해 보내기**다. 내 보관함에는 원본이 남고, 다발이 거쳐 온 경로를 함께 보여 준다.
  - 릴레이할 때 원래 받은 편지와 음성 메모는 넘어가지 않는다(보낸 사람이 나에게만 쓴 것). 대신 릴레이하는 사람이 새 편지를 붙인다.
  - **선물로 받은 꽃다발은 풀 수 없다.** 보낸 사람이 꾸민 그대로 보관한다. 꽃 종류는 도감에 기록된다.
  - **릴레이로 받은 꽃다발은 풀어서 다시 엮을 수 있다.** (아래 "시간이 쌓이는 꽃다발")
  - **릴레이는 내가 받은 꽃으로 직접 엮은 꽃다발만** 할 수 있다.
  - **내가 모아서 엮은 꽃다발과 완성된 채로 받은 꽃다발은 구분해서 보여 준다.** 모아서 만든 쪽이 더 특별하게 느껴져야 한다.
- 설계 메모
  - 받은 꽃 하나하나가 출처(보낸 사람, 날짜, 편지)를 가진 물건이 된다. 꽃다발은 꽃 목록 + 배치 설정 + 포장 선택이다. 보내는 꽃다발과 내가 만든 꽃다발은 같은 데이터 형식을 쓰고, 출처(받음/엮음)만 다르다.
  - 지금의 꽃다발 실험 페이지가 "꽃다발 만들기" 화면의 원형이다. 보낼 다발을 만들 때는 ~~모든 종류에서 고르고~~ → 2026-11-15 변경: 쓸 수 있는 꽃의 범위가 가입 여부에 따라 다름(아래 "보내기 흐름"). 받은 꽃으로 만들 때는 "내가 받은 꽃" 목록에서 골라 꽂는다.

## 시작 흐름: 보내기로 시작 (2026-11-07 정함)
- 서비스의 첫 문은 **보내기**다. 누구나 가입 없이 꽃을 만들어 링크로 보낸다. 선물 하나하나가 초대장이 된다.
- 받는 사람은 링크로 선물을 보고, **저장하려면 가입**한다. 저장한 뒤 "답례로 한 송이 보내기"로 이어진다.
- "꽃 보내 줘" 요청 링크(생일 등)는 가입한 사람의 기능으로 둔다.
- 정한 것
  - **선물은 서버에 저장**한다(지금처럼 페이지 안에 데이터를 넣는 방식으로는 저장한 사람을 기록할 수 없음). 꽃다발 하나 약 1.5KB.
  - **처음 저장한 사람이 주인**이 된다. 링크가 전달돼도 그 뒤로는 보기만 된다. 보낸 사람은 "받음" 표시로 확인한다.
  - **보내는 사람은 가입하지 않는다.** 이름과 캐릭터는 그 기기 브라우저에 기억한다(나중에 가입하면 보낸 기록을 계정으로 옮기는 것은 선택 기능).
  - **같은 기기에서 만드는 횟수 제한**을 둔다(스팸 방지).
  - **저장하지 않은 선물은 처음 연 날부터 일주일 동안 보관**한다. 가입해서 저장하도록 이끄는 장치. 아무도 열지 않은 선물은 일정 기간(예: 30일) 뒤 지운다.
- 정한 것 (2026-11-15)
  - **남은 기간 표시**: 글로 먼저 알려 주고("6일 뒤 시들어요" 같은 표현), 시간이 지날수록 유리돔이 점점 불투명해져 안 보이게 되는 연출을 곁들임.
  - **아무도 열지 않은 선물은 14일** 뒤 지움.
  - **만들기 제한: 하루 1개.** 꽃 보내기가 너무 흔한 행위가 되지 않게 하려는 뜻.
  - **7일이 지난 뒤 가입하면 꽃 모양만 꺼냄**(편지·보이스메모는 지워짐).
- 첫 구현 범위: Supabase 표 하나(선물 데이터, 만든 날, 처음 연 날, 저장한 사람) + "받기 → 가입" 화면. 백엔드를 처음 붙이는 단계.

## 보내기 흐름과 첫 버전 범위 (2026-11-15 정함, UI 작업 전)
- **첫 버전 범위**: 보내기·같이 보내기·받기·유리돔·가입·감사 스냅. 꽃 모음·엮기·도감 화면·릴레이는 다음 단계.
- **보내는 순서**: 꽃이 먼저, 캐릭터는 뒤(링크로 들어온 사람의 목적은 "꽃 보내기"라 첫 화면부터 캐릭터를 만들게 하면 당혹스러움).
  1. 무엇을 보낼까: 한 송이 / 꽃다발
  2. 꽃 정하기: 실제 꽃집처럼 한 송이씩 골라 꽂음. **파사드·필링·소재 순서를 나누지 않음**(꽃다발은 동시에 꽂으며 고르는 것). 한 팔레트에서 분류는 필터·탭 정도로만. 보조 버튼: "알아서 채워 주기"(랜덤), 추천 다발.
  3. 포장지·리본 바꾸기(선택, 기본값은 함께 정해짐). 예전에 말한 "꾸미기"는 꽃 구성·소재·포장·리본·배치를 다듬는 단계였고, 꽃 고르기와 이 작은 옵션으로 나뉨.
  4. 편지: 보이스 메모 자리, 관계(연인/친구) 선택도 여기서(감사 스냅 포즈에 쓰임, 받는 사람에게 묻는 화면이 하나 줄어듦).
  5. 누가 건네줄까요: 저장된 캐릭터 / 기본형 몇 개 / 랜덤 / 직접 만들기.
  6. (선택) 선물코드 상자.
  7. 보내기: 카카오톡 공유 / 링크 복사 / QR.
- **캐릭터 기억**: 가입한 사람(꽃을 받아 저장한 적 있는 사람)은 계정에 캐릭터 저장. 가입 안 한 사람은 같은 기기면 브라우저에 기억, 아니면 기본형·랜덤·다시 만들기. 보내는 데 가입을 요구하지 않음(기존 결정 유지).
- **쓸 수 있는 꽃의 범위** (가입을 간접적으로 홍보):
  - 기본 꽃(2026-11-15 정함, 우선 이 목록): 파사드 장미·튤립, 필링 안개꽃, 소재 유칼립투스. 누구나 항상 씀(첫 경험에서 막혀 보이지 않게, 기념일 빨간 장미 같은 경우 대비).
  - 오늘 들어온 꽃(비회원): 기본 꽃 외에 **파사드·필링·소재마다 3~4종**이 랜덤으로 더 열림. 날마다 바뀜("오늘 꽃시장에 들어온 꽃").
  - 도감 꽃(회원): 받은 적 있는 꽃 종류는 계속 씀. 잠긴 꽃에는 "받으면 열려요" 표시.
  - 도감 꽃을 보내는 다발에 써도 받은 꽃 자체가 줄지 않음(종류를 쓸 수 있게 되는 것). 받은 꽃 한 송이를 실제로 넣는 건 "엮기"(내 보관용) 규칙.
- **같이 보내기 (단체, 2026-11-15 정함)**: 한 다발을 같이 꾸미는 게 아니라, 여러 사람이 각자 꽃·편지·캐릭터를 만들고 받는 사람 한 명이 한꺼번에 받음.
  - 방식: **모아 보내기 링크**. 모으는 사람이 "같이 보내기" 링크를 만들어 단톡방 등에 올림 → 각자 가입 없이 들어와 보내기 흐름 그대로 자기 꽃을 만듦 → 모으는 사람이 링크 하나로 받는 사람에게 보냄 → 받는 사람은 보낸 사람 캐릭터들이 차례로·우르르 나와 각자 꽃을 건네받음(감사 스냅 단체사진과 연결).
  - 릴레이(받은 꽃을 다시 보내기) 방식은 쓰지 않음: 모으는 사람이 가입해야 하고 받기 흐름을 두 번 거치며, "선물로 받은 꽃다발은 넘어가지 않는다" 규칙과 부딪힘.
  - 모집 기한: **최대 7일** 안에서 모으는 사람이 정함.
  - 보내기 전 확인: 모으는 사람은 각자의 **꽃만** 볼 수 있고 편지는 못 봄(편지는 받는 사람만).
  - 두 번째 버전 후보: 여러 사람이 한 다발을 함께 꾸미기.
- **UI 스타일·말투 (2026-11-15 정함)**: ~~레트로 게임풍 UI~~ → 2026-11-15 변경: **바탕 UI는 부드러운 스타일**("from 세헌" 선물 페이지 계열), **레트로는 3D(PS1)에만**. 세부는 사용자가 피그마에서 먼저 만들어 봄. 3D는 화면 픽셀 해상도 300 + 오브젝트별 흔들림(아래 "선물 오브젝트 시안"의 PS1 값). 말투는 다정하게.
- **기기 기준 (2026-11-15 정함)**: 우선 카카오톡 안 웹브라우저 화면 비율(휴대폰 세로)에 맞춰 설계.
- **서비스 이름 (2026-11-15)**: 가제 **꽃망울**(피기 직전의 봉오리, 소리가 "꽃 마음"과 겹침). 링크를 열면 망울이 피어나는 연출과 연결 가능. 확정 전에 상표·도메인 확인 필요(흔한 단어라 이미 쓰는 곳이 있을 수 있음). 함께 나온 후보: 꽃마중, 꽃건네, 꽃편지, 다발다발, 꽃 한 줌. 뺀 것: 꽃과 사랑(연인으로 좁혀 보임), 송이송이(송이버섯 연상).
  - 2026-11-19: 이름은 **꽃망울 그대로**. 로고는 웃는 얼굴 + 꽃(@)을 글자 기호로 조합한 후보(사용자 스케치), "마음의 전달"에 초점.

## UI 스케치 반영 (2026-11-19 정함, 사용자 아이패드 스케치 리뷰)
- 스케치의 보내기 순서(4단계): ① 꽃 꾸미기(포장 포함) → ② 카드 + 선물 → ③ 캐릭터 → ④ 보내기. 받기: 도착(디더링이 풀리며 선명해짐) → 다발 받기 → 카드·보이스메모 → 소포 → 유리돔 → 가입 후 답례 → 보관함.
- **진입 화면**: 큰 버튼은 꽃다발(강조)·한 송이 두 개. **함께 모으기는 그 아래 작은 링크**("여럿이 함께 준비하나요?").
- **함께 모으기 링크 확정**: 팝업 대신 미리보기("지우의 생일 꽃망울") + 확정 버튼.
- **잠긴 꽃**: 기본 꽃 세트는 누구나 씀. 받아서 열리는 꽃은 보너스(11-15 "쓸 수 있는 꽃의 범위" 유지).
- **닉네임**: 캐릭터를 만들 때(③) 받는 것으로 고정. 브라우저에 기억해 다음엔 미리 채움.
- **편지지 색**: 꽃다발의 주된 색으로 자동, 바꾸고 싶은 사람만 색 칩 4~5개에서 고름.
- **보이스메모: 최대 15초** (아래 "보이스 메모"의 15~30초 메모에서 확정).
- **공유 썸네일**: 캐릭터가 빼꼼 나오고 꽃은 가린 템플릿만 씀(열기 전 서프라이즈 유지). 선물마다 이미지를 만들어 저장해야 함(백엔드).
- **소포 열기**: 꽃다발 화면에서 소포 누름(확대) → 소포 한 번 누름(개봉), 두 터치. 기존 결정과 같음.
- **회원 혜택**: 꽃 보관·도감(꽃 모으기) + 세세한 조정(개발자 모드처럼, 예: PS1 값). 감사 스냅·답례 한 송이는 가입 없이도 가능(답례가 퍼지는 통로라서). 가입 유도는 유리돔 한 곳에서만.
  - 메모: 오픈 초반에는 회원 혜택이 약해 보일 수 있음.
- **로그인**: 카카오가 주 방식, 구글은 개발 난이도에 따라 잠재적으로 허용.
- **설정 메뉴**: 효과음·BGM·VR 모드(기울기 센서)를 아이콘 하나로 묶음. 카톡 안 브라우저는 자동 재생이 막히므로 BGM은 기본 꺼짐.
- **소리**: 닌텐도 느낌 8비트 효과음 방향. 음원 구하는 방법은 아직 정하지 않음.
- **영어**: 한국어판 배포 뒤로 미룸. 단 설정에서 언어를 바꿀 수 있게 할 예정이므로, 처음부터 화면 문구를 한 파일에 모아 두기.
- **보관함에서 다시 보기**: 포즈 장면을 건너뛰고 바라보기로 바로 감. "다시 받아 보기" 버튼을 따로 둠.
- **개발자 피드백 우편함**: 보내기 완료 화면과 보관함에만 둠(받기 화면에는 두지 않음).
- **카드 먼저**: 카드를 먼저 누르도록 멘트로 이끔. 소포를 먼저 누르면 "○○의 카드가 함께 도착했어요!"로 카드 쪽으로 안내(2026-11-19 보완: 카드를 열기 전에는 소포가 열리지 않음, 아래 "구현 전 확인 답변").

## 미니 다발 (꽃 한 송이 선물의 모양, 2026-11-07)

- 구현: 꽃다발 실험 페이지에 반영됨("크라프트 미니" 포장, 빨간 장미, 매달린 태그, 2026-11-07 링크 업데이트).

## 시간이 쌓이는 꽃다발 (2026-11-07 정함)

## 보내는 사람 캐릭터 (2026-11-07 메모, 아직 결정 아님)
- 보내는 사람이 자기를 나타내는 작은 캐릭터를 만든다. 꽃다발을 받으면 꽃을 보낸 사람들의 귀여운 캐릭터가 함께 보인다.
- 두 가지 방식
  - **닮은 캐릭터**: 얼굴형, 피부색, 머리 모양과 색, 눈, 안경, 옷 색 등을 골라 자기와 비슷하게 만든다(게임기의 자기 캐릭터 만들기와 비슷한 개념, 디자인은 우리만의 것).
  - **동물 페르소나**: 강아지, 고양이, 토끼 등 동물을 고르고 털색, 무늬, 소품을 정한다.
- 추천: 큰 머리·작은 몸의 공용 몸 하나에 머리 종류(사람/강아지/고양이/토끼)만 고르게 해서 한 시스템으로 만든다. 동물부터 만든다(부품이 적고 로우폴리로도 금방 귀여움). 닮은 캐릭터는 머리 모양 종류가 작업의 대부분이다.
- 설계 메모
  - 꽃과 같은 방식: 캐릭터도 **값 몇 개로 저장**하고 코드로 그린다(로우폴리 + PS1). 꽃 생성기의 템플릿·등록·자동 슬라이더 구조를 그대로 써서 "캐릭터 템플릿"을 추가하는 형태가 된다. 꽃 생성기 v1 다음 순서(v1.1, 핸드오프 9장).
  - 값만 저장하므로 계정 없이도 선물 데이터에 캐릭터를 함께 담아 보낼 수 있다(보내는 사람은 가입하지 않으므로 브라우저에 기억).
  - 보이는 곳: 꽃을 누르면 보낸 사람 캐릭터, "이 다발에 담긴 사람들" 목록, 릴레이 경로, 보관함. 목록용 작은 아이콘은 3D 캐릭터를 작은 픽셀 그림으로 미리 그려 쓴다.
  - 정원 프로젝트의 "집에서 나와 답장을 전하는 주인 캐릭터"와 같은 것으로 쓸 수 있다.
  - 주의: 특정 게임의 캐릭터 모양이나 이름을 따라 하지 않고 고유한 스타일로 만든다.
- 차별점: 조사한 꽃 선물 서비스들에는 보내는 사람의 캐릭터가 없었다.
- 구현: 캐릭터 실험 페이지에 6종(강아지, 고양이, 토끼, 사람, 공룡, 로봇) 상반신, 눈 색·안경 공통 옵션, 강아지·고양이 털 무늬가 있다.

- 목적: 카카오톡 선물하기 경험에 매끄럽게 들어가기. 기프티콘이 먼저 도착하면 서프라이즈가 없으니, **꽃이 먼저, 선물은 마지막**에 나오게 한다.
- 방법: 보내는 사람이 선물하기에서 **코드선물**로 결제 → 생긴 선물코드를 우리 꽃 카드의 "선물 상자"에 붙여 넣음 → 카톡에는 꽃 카드 하나만 보냄(카카오톡 공유 SDK).
- 받는 흐름: 꽃 카드 → 건네기 → 바라보기·편지 → ~~편지를 닫으면~~ (2026-11-19: 처음부터) 꽃다발 옆에 작은 선물 상자 → 누르면 PS1 오브젝트(예: 커피 컵)가 튀어나오고 "카카오톡에서 받기"(코드 복사 + 선물함 등록 안내).
- 오브젝트: 상품 사진이 아니라 **우리 템플릿**(커피, 케이크, 치킨, 아이스크림, 화장품, 상품권 봉투 등 20~30개)에서 고르고 색·크기만 바꾼다. 처음엔 카테고리 고르기만, 나중에 한 줄 문구 → AI가 템플릿과 값을 고르는 방식(서버 함수, 결과 검증·캐시).
- 기존 방향과의 관계: 앞서 "기프티콘은 직접 다루지 않는다"고 했던 것을 바꾼다. 결제·바코드는 여전히 다루지 않지만, **사용자가 넣은 선물코드를 전달**한다. 스크린샷 업로드는 받지 않는다(바코드·상표·비용 문제).
- 보안 기본값 (처음부터)
  - 주소를 여는 것만으로 주인을 정하지 않는다. 사람이 **상자를 눌렀을 때** 기록(링크 미리보기·보안 앱의 자동 접속 대비).
  - 선물 표는 브라우저에서 직접 읽지 못하게(Supabase RLS로 막고, 서버 함수가 선물 하나만 돌려줌). 코드는 상자를 여는 함수에서만.
  - **서버도 못 읽는 암호화**: 코드는 브라우저에서 암호화하고, 열쇠는 링크의 `#` 뒷부분에만 둔다(서버로 전송되지 않음).
  - 편지는 항상 글자로만 표시(XSS 방지). 선물 ID는 길고 무작위. 반복 시도 제한.
  - 처음 연 기기에서만 상자가 열림 + 다른 브라우저로 다시 열 때를 위한 짧은 확인 질문(보낸 사람이 정함).
  - 코드는 로그·오류 추적에 남기지 않고, 상자를 연 뒤 또는 7일 뒤 삭제.
  - 화면에 "보낸 사람이 넣은 코드예요"(우리는 진위를 보증하지 않음), "카카오 로그인·결제 정보를 묻지 않아요"(피싱 대비).
- 시작 전 확인할 것
  - 코드선물 유의사항과 선물하기 약관(양도·제3자 서비스·부정 사용 조항) → 카카오 고객센터에 서면 문의.
  - 카카오톡 공유 카드가 링크의 `#` 부분을 그대로 넘기는지 실제 테스트.
  - 카카오 디벨로퍼스 앱 등록(JavaScript SDK 도메인, 제품 링크 관리 웹 도메인). 공유 API는 쿼터 안에서 무료.
- 순서: 확인이 끝나기 전에는 기본 흐름을 "꽃 카드 + 오브젝트"로 만들고, 코드 상자는 켜고 끌 수 있는 기능으로 설계해 둔다.
- **선물 오브젝트 시안 (2026-11-15, 아티팩트 "꽃망울 · 선물 오브젝트")**
  - 템플릿 25종: 커피, 아이스 음료, 조각·홀케이크, 치킨, 아이스크림, 립스틱, 상품권, 텀블러, 향수, 립글로우, 배달 봉투, 쇼핑백, 막대 과자, 뷰티 카드, 마카롱, 쿠키, 초콜릿, 핸드크림, 책, 과일 바구니, 고기 세트, 목도리, 곰 인형, **미스터리 상자**(분류가 힘든 선물: 보내는 사람이 이름을 직접 적고 꼬리표에 표시, 14자). 2025 카카오 선물하기 랭킹(교환권·위시리스트 상위)을 근거로 고름. 브랜드 모양·로고는 쓰지 않음.
  - 담는 것: 선물 상자 대신 **빵빵한 크라프트 종이봉투 소포**. 앞쪽 개봉선을 뜯으면 선물이 튀어나옴.
  - 기본값: 선물 크기 79%(꽃이 주인공).
  - **PS1 값 (2026-11-15 정함, 꽃다발 2배 기준)**: 화면 픽셀 해상도 300, 꼭짓점 흔들림은 꽃다발 550 · 소포 350 · 선물 820. 흔들림은 오브젝트 묶음마다 따로, 픽셀 크기는 화면 전체에 하나. 디지털 꽃다발이지만 조금 레트로하게 보이도록 PS1 효과를 주려던 처음 기획에 맞는 정도.
  - **꽃다발 : 소포 크기 = 2 : 1** (예전 "from 세헌" 꽃다발 기준, 시안의 "꽃다발과 함께 보기").
  - 보기: 드래그로 상하좌우 회전(소포와 함께), 두 손가락 확대.
  - **색·크기 선택은 실제 UI에서 뺌** (2026-11-16): 보내는 사람이 고를 것이 늘어나는 부담이 더 큼. 시안에는 실험용으로 남겨 둠. 색은 자동으로 정함(방식은 미정, 추천: 꽃다발의 주된 색에서 뽑기), 크기는 79% 고정.
  - 개봉선 띠는 손잡이 쪽부터 마디마다 말리며 뜯김(2026-11-16).
  - **나중에 구성할 받기 순서**: 꽃다발 옆 소포를 누르면 소포만 크게 나옴 → 거기서 다시 눌러 선물이 나옴(두 단계).

## 로그인: 카카오 연동 (2026-11-14 정함)
- 가입하는 사람은 **꽃을 받아 간직하려는 사람**뿐(보내는 사람은 가입하지 않음). 받는 사람 대부분이 카톡 안 브라우저로 열기 때문에 "가입하고 꽃 꺼내기"가 버튼 한 번이 되도록 **카카오 로그인**을 주 방식으로 한다. 카카오를 안 쓰는 사람용 보조 수단(이메일 링크 또는 이메일 + 비밀번호)은 나중에 정한다. 아이디 + 비밀번호만 받는 방식은 계정을 되찾을 길이 없어 쓰지 않는다.
- 받는 정보는 최소: **로그인 고유 ID + 닉네임**만 필수. 이메일은 받지 않거나 선택(카카오 이메일 동의 항목은 비즈 앱에서만 가능, Supabase의 "Allow users without an email" 켜기). 생일은 "생일에 꽃 보내 줘" 기능을 만들 때 따로 동의받는다. 전화번호·실명·주소는 받지 않는다.
- 구현: Supabase Auth의 카카오 제공자(`signInWithOAuth({ provider: 'kakao' })`). 우리 코드는 카카오 토큰을 직접 다루지 않고 저장하지도 않는다.
- 보안 체크리스트
  - 카카오 디벨로퍼스: Client Secret 켜기(값은 Supabase 설정에만), 리다이렉트 URI 정확히 등록, OpenID Connect 켜기(nonce), 동의 항목은 닉네임만, 콘솔 계정 2단계 인증.
  - 키 구분: JavaScript 키(공유 SDK, 도메인 등록으로 제한)만 브라우저에. REST 시크릿·Admin 키는 브라우저·깃허브에 절대 두지 않는다.
  - 모든 표에 RLS: 로그인한 사용자 ID와 같은 줄만 읽기·쓰기.
  - 이메일이 같다는 이유로 계정을 자동으로 합치지 않는다(연결은 로그인한 상태에서 사용자가 직접).
  - 카카오 쪽 연결 해제·계정 상태 변경 알림(웹훅)을 받아 계정 정리.
  - 토큰·인가 코드·선물코드는 로그에 남기지 않는다.
  - 카톡 안 브라우저에서 로그인(PKCE 쿠키)이 끝까지 이어지는지 실제 기기로 시험.
- 가입 후 이점: 선물코드 다시 보기를 "처음 연 기기" 대신 **계정**에 묶을 수 있다.
- 법적으로 할 것: 개인정보 처리방침, 가입 시 필수·선택 동의 분리, 만 14세 이상만 가입(법정대리인 동의 회피), 탈퇴 시 보관함·편지·보이스메모 실제 삭제. 공개 전 처리방침 검토받기.

## 유리돔: 가입 전 받은 꽃의 모습 (2026-11-08 메모, 아직 결정 아님)
- 가입하지 않은 사람이 받은 꽃(다발)은 **유리돔(글라스 클로슈)을 씌운 모습**으로 보여 준다. 어린 왕자의 장미에서 가져온 모티브.
- 뜻: 일주일 보관("처음 연 날부터 7일") 규칙을 문구 대신 그림으로 전한다. 돔 안의 꽃은 아직 "맡겨 둔" 상태이고, 가입해서 저장하면 돔을 들어 올려 꽃을 꺼낸다. 위의 "정할 것"(남은 기간을 어떻게 보여 줄지)의 답 후보.
- 연출 후보
  - 날이 갈수록 돔에 김이 서리거나 먼지가 앉아 꽃과 편지가 조금씩 흐려진다. 마지막 날에는 꽃이 고개를 숙인다("6일 뒤 시들어요" 표현과 연결).
  - 7일이 지나면 돔 안의 편지는 더 이상 읽을 수 없고 꽃 모양만 남는다. 지운다는 사실을 간접적으로 전하는 장면.
  - 저장(가입) 순간: 돔이 들려 올라가며 꽃이 손에 들어오는 짧은 애니메이션 → 보관함·도감으로 이어짐.
- 구현 메모
  - PS1 스타일에 맞춰 반투명은 **디더 투명**(포장지 속포장지와 같은 재질)으로 그린다. 반사 하이라이트는 흰 선 몇 개 정도.
  - 돔은 꽃다발 데이터와 별개인 화면 장식이라 저장 형식은 바뀌지 않는다. 남은 날짜(처음 연 날 기준)만 있으면 서리 정도를 계산할 수 있다.

## QR로 전달: 깜짝 이벤트 (2026-11-08 메모, 아직 결정 아님)
- 링크를 메시지로 보내는 대신, 선물 링크를 **QR 코드로 화면에 띄우거나 출력**해서 건넨다. 만나서 휴대폰 화면을 보여 주거나, 실물 카드·편지·케이크 토퍼·포장 상자에 붙여 두면 상대가 찍어서 꽃을 받는다. 깜짝 이벤트용.
- 설계 메모
  - QR은 기존 선물 링크를 그대로 담는다. 저장·주인 규칙(처음 저장한 사람이 주인, 처음 연 날부터 일주일 보관)은 링크와 같다.
  - 보내기 완료 화면에 "링크 복사" 옆에 "QR로 보여 주기"를 둔다. 전체 화면으로 크게 띄우는 모드와, 인쇄용 카드(PNG·PDF 내려받기) 두 가지.
  - QR 카드 디자인: QR 가운데나 옆에 보낸 사람 캐릭터와 미니 다발 아이콘(PS1 픽셀 그림). 무엇이 들었는지 미리 보이지 않게 "찍어 보세요" 정도만.
  - 실물에 붙이는 경우 받는 사람이 언제 찍을지 모르므로, 일주일 보관 기준이 "만든 날"이 아니라 "처음 연 날"인 지금 결정이 잘 맞는다. 아무도 열지 않은 선물의 삭제 기간(예: 30일)은 실물 카드용으로 더 길게 둘지 정해야 한다.
  - 주의: 화면을 찍은 다른 사람이 먼저 열어 저장하면 주인이 바뀐다. 필요하면 QR 선물에 짧은 확인 문구(받는 사람만 아는 답)를 선택으로 붙인다.
  - QR 생성은 브라우저 안에서 라이브러리로 만들면 되고 서버 작업은 없다.
- **깜짝 카메라 버전** (옵션): QR 카드를 평범한 다른 QR처럼 꾸며서, 찍기 전까지는 꽃 선물인 줄 모르게 한다. 찍는 순간 꽃이 열리는 반전.
  - 위장 디자인 후보: 와이파이 안내, 메뉴판, 쿠폰·할인권, 설문, 행사 입장권, 택배 안내처럼 흔한 생활 QR. 문구와 레이아웃만 흉내 낸 **가상의 디자인**이고, 실제 회사·기관의 이름이나 로고는 쓰지 않는다(사칭처럼 보이면 안 됨).
  - 찍었을 때 첫 화면: 위장 문구가 잠깐 보이다가 지지직 PS1 화면 전환 → 꽃과 보낸 사람 캐릭터가 등장("속았지?" 같은 한 줄은 보내는 사람이 고름).
  - 인쇄용으로만 의미가 있으므로 인쇄 카드 모드에서 고르는 옵션으로 둔다. 일반 QR 카드와 같은 선물 링크를 담고, 저장·주인 규칙도 같다.

## 감사 스냅: 꽃과 함께 찍는 네컷 사진 (2026-11-08 메모, 아직 결정 아님)
- 꽃을 받은 사람이 받은 꽃(다발)과 함께 **인생네컷 같은 스냅사진**을 찍어 감사 메시지와 함께 보낸 사람에게 보낸다. 사진은 꾸밀 수 있다(프레임, 스티커, 글씨).
- 받는 시점에는 보낸 사람의 캐릭터 정보도 선물 데이터에 들어 있으므로, 사진에 **받은 사람 캐릭터 + 보낸 사람 캐릭터 + 꽃**이 함께 나온다. 여러 사람에게 받은 엮은 다발이면 담긴 사람들이 **우르르 단체사진**으로 나온다.
- 설계 메모
  - 같은 3D 장면을 정해진 구도(4컷 = 카메라 4개, 또는 포즈 4개)로 저해상도 PS1 렌더한 뒤 한 장의 세로 이미지로 합친다. 사진 파일 자체를 서버에 둘 필요 없이 "장면 데이터 + 꾸미기 데이터"만 보내면 받는 쪽에서 다시 그릴 수 있다(공유용 PNG 내려받기는 별도).
  - 포즈: 지금 캐릭터 실험의 "큰 다발 들고 빼꼼" 같은 자세를 포즈 목록으로 확장한다(꽃 안기, 브이, 볼 맞대기, 고개 갸웃).
  - 단체사진: 인원 수에 따라 줄 배치(앞줄 앉기, 뒷줄 서기)를 자동으로. 많으면 작은 아이콘 크기로 우르르.

## 패턴 재질: 사인 합성으로 그리는 무늬 (2026-11-08 메모)
- 출발점: 얼룩말 무늬를 여러 사인 함수의 합성으로 보고, 몸 전체 무늬를 uv처럼 펼쳐 설명한 교양과학 책의 관점(작업자가 인상 깊게 읽은 부분).
- 생각: 무늬를 형태의 함수로 정의하면 모양 코드는 그대로 두고 **패턴 재질** 하나만 등록하면 된다. 꽃 생성기 형태 단계가 모든 점에 `uv`, `along`(밑동→끝), `across`(가운데→가장자리)를 남기는 이유와 맞는다.
- 쓸 곳
  - **꽃잎**: 가장자리만 다른 색(카네이션 피코티, `across` 근처 1), 튤립의 불꽃 줄무늬(`along` 방향 사인), 알스트로메리아·백합의 점박이, 꽃잎 맥, 스프레이 장미의 그라데이션
  - **포장지**: 도트, 스트라이프, 체크, 작은 꽃무늬. 이미지 없이 함수만으로 포장지 종류를 늘린다.
  - **캐릭터 털**: 점박이, 얼룩(비글·바둑이), 줄무늬(태비), 삼색. 저장되는 건 무늬 종류, 색 번호, 양, 크기, 시드뿐이다.
- 구현 원칙
  - 꼭짓점 색으로는 로우폴리에서 무늬가 뭉개진다. **픽셀 단위로 계산하는 셰이더 재질**로 만든다. PS1 저해상도·디더와 잘 어울린다.
  - 둥근 표면(캐릭터 머리)은 uv를 펼치면 경계에서 무늬가 끊긴다. **3D 위치로 계산**하면 이음새가 없다. 평평한 부품(꽃잎, 포장지)은 uv로 충분하다.
  - 규칙적인 무늬는 사인 합성이 강하다. 불규칙한 무늬(얼룩말처럼 갈라지는)는 반응-확산(튜링 패턴)이 자연스럽지만, PS1 해상도에서는 사인 합성에 노이즈를 조금 섞는 것으로 충분할 가능성이 높다.
  - 꽃 생성기에서는 `registerMaterial('pattern', …)` 하나로 들어간다. 무늬 종류별 params로 편집기 슬라이더가 자동으로 생긴다.
- 시험 결과(2026-11-08): 캐릭터 실험 페이지의 강아지·고양이에 **털 색 + 무늬 색(두 색) + 무늬 종류(점박이/얼룩/줄무늬) + 무늬 양·크기 슬라이더 + 다시 섞기**를 붙였다. 3D 위치 기반 셰이더라 이음새가 없고, 캐릭터 데이터는 약 95바이트다. 얼룩무늬일 때 강아지 귀는 무늬 색을 쓴다.

## 소재(초록 잎) 공급 (2026-11-07 메모, 아직 결정 아님)
- 문제: 예쁜 꽃다발에는 소재(유칼립투스, 보리사초 등)가 많이 필요하다. 받은 꽃만으로는 다발이 휑할 수 있다.
- 사용자 제안
  1. **받은 수에 비례해 기본 소재 제공**: 꽃을 받을수록 기본 소재가 쌓인다.
  2. **소재 한 줄기 선물하기**: 꽃이 부담스러운 관계에서 더 가볍게 보낼 수 있는 선물. 받는 사람의 다발을 채워 주는 역할도 한다.
  3. **미니 다발에 소재 동봉**: 한 송이 선물에 소재 2~3줄기가 함께 온다(위 "미니 다발").
- 설계 메모
  - 방식들은 함께 쓸 수 있다. **기본 소재**(이야기 없음)와 **선물받은 소재**(보낸 사람·날짜가 있는 이야기 있음)를 구분하면, 다발 안에서 이야기가 있는 줄기와 없는 줄기가 섞인다.
  - 기본 소재 제공량 예: 꽃 1송이를 받을 때마다 기본 소재 2줄기. 기본 소재는 흔한 종류만, 특별한 소재는 선물로만 얻게 하면 선물의 가치가 유지된다.
  - 소재 선물도 도감에 기록된다(소재 칸).
  - 잎 소재형 템플릿 핸드오프(`handoffs/foliage-v1.2.md`)에서 종 JSON에 `category: "foliage"`, `basicSupply` 칸을 미리 둔다.

## 받은 꽃 도감 (보관함)
- 받은 꽃과 꽃다발을 포켓몬 도감처럼 보관한다.
  - **도감**: 받은 꽃의 종류를 모은다. 아직 못 받은 종은 실루엣으로 보인다. 종마다 처음 받은 날, 받은 횟수, 보낸 사람을 기록한다.
  - **시간순 보관함**: 받은 꽃·꽃다발과 내가 엮은 꽃다발을 날짜순으로 다시 열어 본다.
- 설계 메모
  - 꽃다발은 데이터만으로 다시 그려지므로(25송이에 약 1.5KB) 보관 비용이 거의 없다. 목록은 작은 썸네일로 보여 주고, 열었을 때만 3D로 그린다.
  - 도감은 꽃 종류가 많을수록 재미있어지므로, 꽃 생성기로 종을 늘리는 일과 직접 연결된다.

## 확장: 꽃집·향 브랜드 협업 (2026-11-07 메모, 아직 결정 아님)
- 인스타그램 기반 꽃집, 향 관련 상품(향수, 캔들, 디퓨저) 브랜드와 협찬·광고로 확장
- 서비스 분위기를 해치지 않는 방식 후보
  1. **브랜드 시그니처 꽃·포장지**: 꽃집이 디자인한 꽃 종류나 포장지를 기간 한정으로 낸다. 도감에 "○○ 꽃집" 출처가 붙는다. 꽃 생성기의 종 설계 JSON에 출처(credit) 칸만 있으면 된다.

  3. **꽃다발의 향**: 꽃 종류마다 향 노트를 붙이고, 어울리는 향 상품을 소개한다.

  - 사용자가 생기기 전에는 협업 제안이 어렵다. 지금 할 일은 종 설계에 출처 칸, 포장지 목록 같은 "나중에 붙일 자리"를 남겨 두는 정도다.

## 포장지 2겹: 겉포장지 + 속포장지
- **겉포장지**: 지금처럼 꽃 바깥을 감싸는 불투명한 종이
- **속포장지**: 그 안쪽에 투명하게 있는 필름(셀로판, OPP 같은 느낌). 겉포장지보다 조금 높고 꽃에 더 가깝게, 가장자리는 구겨진 듯 각지게
- 구현 메모
  - 반투명은 알파 블렌딩 대신 **디더 투명(점 패턴으로 일부 픽셀만 그리기)**을 우선 검토한다. PS1 느낌과 맞고, 꽃·종이와의 그리기 순서 문제가 생기지 않는다.
  - 꽃 생성기 구조에서는 재질 하나(`registerMaterial('film')`)와 포장지 부품으로 붙이는 방식이 자연스럽다.
  - 꽃 생성기 v1 범위는 아니다(꽃다발 배치·포장지는 v1에서 바꾸지 않음).

## 보이스 메모
- 꽃 한 송이마다 쪽지 대신(또는 함께) **음성 메모**를 남긴다.
- 듣는 방식 두 가지
  - **한 송이씩**: 꽃을 누르면 그 꽃의 메모가 재생된다. 보관함에서 하나씩 다시 듣는다.
  - **잔잔하게 전부**: 꽃다발 속 메모들이 작은 소리로 겹쳐 흘러, 대화 소리가 끊이지 않게 들린다. 받은 꽃으로 꽃다발을 엮으면, 여러 사람의 목소리가 한 다발에 모이게 된다.
- 설계 메모 (아직 결정 아님)
  - 녹음: 브라우저 MediaRecorder. 기기마다 녹음 형식이 달라 재생 호환성을 확인해야 한다. Claude 아티팩트 안에서는 마이크가 막혀 있어서, 녹음은 직접 호스팅한 페이지에서만 가능하다.
  - 용량: 송이 데이터(약 60바이트)와 달리 음성은 30초에 약 100KB 이상이다. 길이 제한(15~30초)과 저비트레이트 압축이 필요하고, 저장은 Supabase Storage를 쓴다.
  - 잔잔하게 재생: 한꺼번에 다 틀면 소음이 되므로 동시에 3~4개만 겹치고 차례로 바꿔 튼다. 꽃 위치에 맞춘 입체 음향으로 다발을 돌리면 목소리 방향도 따라 돈다.
  - 휴대폰은 사용자가 한 번 눌러야 소리가 나므로 "듣기" 버튼이 필요하다.
  - 권한: 받는 사람만 듣는다. 목소리는 개인정보라 삭제 기능도 필요하다. 릴레이할 때는 넘어가지 않는다.
  - 선택: PS1 느낌에 맞춘 로파이 필터(저역 통과, 비트 감소)
  - 비회원 일주일 보관과 함께 쓰면, 저장하지 않은 선물의 음성 파일도 같은 기간 뒤 지운다.

- 시험 환경: 컴퓨터에서는 VS Code Live Server(localhost)로 녹음이 된다. 휴대폰 시험은 https가 필요해서 VS Code 포트 전달(devtunnels) 주소로 연다.

## 꽃다발 레퍼런스 (2026-11-14, 인스타그램 저장 이미지 7장)
- **포장지는 재질 차이가 가장 크다.**
  - 불투명 종이: 결 있는 흰 종이로 크게 감싸기, 검정 무광지. 지금의 종이 포장 계열.
  - 비치는 천(오간자): 검정·짙은 초록, 가장자리 박음질. → 디더 투명 + 테두리선 하나로 표현.
  - 레이스: 꽃무늬가 비치는 포장 + 연분홍 리본. → 디더 투명 + 무늬 재질.
  - 구긴 습자지: 진한 파랑, 꽃 색과 강하게 대비. 각진 로우폴리와 잘 맞음.
  - 두 겹: 체크무늬 종이 + 투명 필름. 위 "포장지 2겹" 메모와 같음. 체크·도트는 "패턴 재질"로.
- **카드·태그 위치**: 포장지 맨 위 앞쪽에 비스듬히 꽂힌 카드(큰 꽃다발과 같음), 끈에 매달린 태그(미니 다발과 같음), 꽃 사이에 작게 꽂힌 검정 태그(새 변형).
- **구성 방식 세 가지**
  - 풍성한 섞음: 여러 종류 + 안개처럼 흩어지는 가는 풀을 넓게. 지금 파사드 배치와 비슷.
  - 한 종류 3~5송이: 거베라 몇 송이 + 풀 한두 줄기. 미니 다발의 확장판 후보.
  - 두 종류 대비: 튤립 + 라넌큘러스처럼 모양이 다른 두 꽃을 섞기.
- **아직 없는 꽃** (자주 보인 순): 거베라(일반·스파이더), 튤립, 라넌큘러스, 코스모스, 천일홍, 카네이션, 달리아, 백합 봉오리, 네리네, 가는 풀(그래스).
  - 거베라와 가는 풀이 거의 모든 레퍼런스에 나온다. 거베라는 납작한 원판 + 방사형 꽃잎이라 꽃 생성기에 넣기 쉬움 → 다음 종 추가 1순위 후보.
- **들꽃 다발 + 크라프트 포장** (2026-11-14 추가, 사용자가 "귀엽다"고 한 것): 코스모스(흰색) 큰 꽃 몇 송이가 중심, 사이사이 보라 아스터, 노랑·주황 작은 국화류, 분홍 천일홍, 하늘색 작은 꽃(블루스타), 흰 레이스플라워를 높이 들쭉날쭉 꽂음. 포장은 무지 크라프트지 한 겹을 넓게 펼쳐 감싸고 아래는 구겨 묶은 뒤 흰 리본을 길게 늘어뜨림.
  - 우리에게 맞는 점: 꽃이 작고 많아 로우폴리로도 "들꽃" 느낌을 내기 쉽고, 크라프트지는 미니 다발 포장과 같은 재질이라 큰 다발 버전으로 바로 이어진다.
  - 필요한 것: 코스모스·천일홍(위 목록에 이미 있음), 아스터·블루스타·레이스플라워(새로 추가). 줄기 길이를 들쭉날쭉하게 하는 "자연스러운 높이 편차" 배치 옵션.
- **요즘 유행하는 꽃다발** (2026-11-15 추가, 인스타그램 이미지 3장): 둥글게 꽉 채우지 않고 높낮이를 크게 두고 군데군데 비워서 "정원에서 막 꺾어 온" 느낌.
  - 소재: 위로 튀어나오는 선(클레마티스 덩굴, 가는 가지, 어두운 띠 잎), 아래로 늘어지는 덩굴·꽃줄기·긴 리본, 큰 꽃 사이를 채우는 자잘한 흰 꽃(레이스플라워·안개꽃), 깊이를 주는 짙은 와인색 꽃(스카비오사)과 어두운 잎.
  - 높낮이: 세 층(가운데 낮게 큰 꽃 — 장미·라넌큘러스·리시안셔스 / 그 위로 들쭉날쭉한 가는 줄기 꽃 — 코스모스·거베라·네리네 / 한쪽으로 가장 높이 솟는 길쭉한 꽃 — 델피니움·금어초). 한쪽은 높고 길게, 반대쪽은 낮고 옆으로 퍼지는 비대칭. 꽃 얼굴 방향이 제각각.
  - 포장: 무광 종이 한 겹을 꽃다발보다 높게 크게 감싸고 리본을 길게 늘어뜨림(그레이 블루 종이 + 하늘색 리본, 베이지 종이 + 남색 리본).
  - 우리 쪽으로 가져올 것: 배치 옵션 "자연스러운 높이 편차" + "한쪽으로 치우친 높이" + "꽃마다 얼굴 방향 무작위". 채우는 잎과 별개로 **선을 만드는 소재**(덩굴, 가는 가지, 띠 잎) 종류 추가. 감사 스냅의 임시 무작위 꽃다발(둥근 반구형)도 나중에 이 배치를 쓰면 좋음.
  - 아직 없는 꽃 추가 후보: 델피니움, 금어초, 리시안셔스, 스카비오사, 클레마티스, 호접란.

## 웹 오픈 이후: 위젯·앱·애플워치 (2026-11-19 메모, 앱 구조만 정함)

  - 앱 전용: 위젯, 꽃 도착 알림, 라이브 배경화면(안드로이드), 애플워치.

  - 앱 전용 콘텐츠를 두지 않는 이유: 받는 사람은 카톡 안 웹에서 가입하므로 가입 직후 앱 설치를 요구하면 이탈이 큼. 웹·앱 코드가 갈라지면 혼자 관리하기 무거움.
  - 웹 코드에 미리 할 것: 앱에 담기 좋게 만들어 두기(화면 문구 한 파일, 로그인·저장 로직을 화면과 분리).

- 조사한 제약
  - iOS 위젯은 정해진 시간에 찍은 정지 화면을 보여 주는 방식이라 직접 만든 애니메이션·3D(SceneKit)·센서를 쓸 수 없음 → 위젯 안에서 실시간으로 기울어지는 3D는 불가.
  - iOS 26 "공간 장면(Spatial Scene)": 사진을 잠금화면 배경으로 지정하면 기울일 때 깊이감 있게 움직임(시스템 기능, iPhone 12 이상). 우리가 좋은 꽃다발 이미지만 만들어 주면 됨.
  - 안드로이드는 라이브 배경화면으로 자이로 센서 + 실시간 3D 가능.
  - 애플워치: SceneKit은 watchOS 26에서 지원 중단 예고, RealityKit은 워치에서 안 됨 → 미리 그린 여러 각도 이미지를 디지털 크라운으로 넘기는 "가짜 3D"가 현실적(PS1 느낌과도 맞음).
- 추천 방향

  2. 앱은 회원 전용 "보관함 앱": 보관함·도감·포토박스·위젯·꽃 도착 알림. 보내기는 계속 설치 없이 웹에서.
  3. 위젯: 여러 각도를 미리 렌더해 시간에 따라 천천히 돌거나 버튼으로 돌리기. 링크 붙여 넣기보다 회원 계정의 보관함에서 고르기(주인·7일 규칙과 맞음).
  4. 기술: 웹 코드를 앱 껍데기(Capacitor 등)에 담고, 위젯·워치만 작은 네이티브 코드.
